## Техническое задание: игра «Классические шашки» с LLM‑комментатором

### 1. Цель проекта

Разработать веб‑игру «Классические русские шашки» (8×8, дамка, взятие обязательно) с:

* надёжной игровой логикой на бэкенде;
* качественной, стильной графикой и анимациями на фронтенде;
* «живым» комментарием от LLM после каждого хода ИИ (характер, эмоции, подсказки, но без нарушения правил).

---

### 2. Общие требования

**Платформа:** веб‑приложение (браузер).  

**Стек:**

* Backend: Java, Spring Boot.

* Frontend: React + TypeScript + Vite.

* ИИ‑логика: минимакс с альфа‑бета отсечением (на бэкенде).

* LLM‑сервис: отдельный микросервис либо вызов из Java (формат запроса/ответа — JSON).

* Инфраструктура: Docker (контейнеры для backend, frontend, llm‑service).

Учитывай AGENTS.md

**UX/UI:**

* адаптивная верстка (десктоп);

* понятная индикация: чей ход, возможные ходы, взятия, превращение в дамку;

* анимации перемещения шашек и взятий;

* звуковое сопровождение (опционально): клик, ход, взятие.

---

### 3. Игровая логика (Backend, Java, Spring Boot)

#### 3.1. Состояние игры

Хранить состояние в Database (Docker): PostgreSQL 16 (для масштабируемости). Структура состояния:

* `board[8][8]`: клетка содержит тип фигуры и цвет (пусто, простая белая, простая чёрная, дамка белая, дамка чёрная).

* `currentPlayer`: WHITE или BLACK.

* `lastMove`: координаты и тип хода (обычный, взятие, превращение).

* `gameStatus`: IN\_PROGRESS, WHITE\_WON, BLACK\_WON, DRAW.

* `forcedCapture`: флаг, указывающий, что сейчас обязательно взятие (если есть варианты взятия).


#### 3.2. Валидация ходов

Реализовать строгую валидацию по правилам русских шашек:

* простой ход вперёд по диагонали на 1 клетку;

* взятие прыжком через шашку соперника (возможно серийное взятие);

* дамка ходит и бьёт по диагонали на любое количество клеток;

* при наличии взятия игрок обязан бить;

* превращение в дамку при достижении противоположного края.


Валидатор должен возвращать:

* список допустимых ходов для текущего игрока;

* флаг «обязательно взятие» и список ходов‑взятий.


#### 3.3. Применение хода и определение конца игры

* Применить ход, обновить доску, проверить серию взятий (если возможно продолжение взятия — разрешить его в рамках одного «хода»).

* Определить конец игры:

  * нет допустимых ходов у соперника — победа текущего игрока;
  * ничья при повторении позиции N раз или по правилу «патовых» позиций (можно начать с простого: ничья по взаимному согласию или после 50 ходов без взятий).


#### 3.4. Эндпоинты API (REST)

1. `POST /game/start` — создать новую игру, вернуть ID и начальное состояние.
2. `GET /game/{id}` — получить текущее состояние игры.
3. `POST /game/{id}/move` — выполнить ход игрока (валидация, применение, проверка конца игры). В ответе: новое состояние, результат хода, флаг окончания игры.
4. `POST /game/{id}/ai-move` — сделать ход ИИ:

   * вызвать минимакс‑алгоритм;

   * получить выбранный ход;

   * передать состояние и ход в LLM‑сервис;

   * вернуть: ход ИИ, комментарий LLM, новое состояние, статус игры.

### 4. ИИ‑оппонент (минимакс + альфа‑бета)

**Требования к алгоритму:**

* глубина поиска: 4–6 полуходов (настраиваемый параметр);

* эвристика оценки позиции:

  * материал (шашка = 1, дамка = 1.5–2);

  * позиция на доске (бонус за центр, за продвижение вперёд);

  * мобильность (количество доступных ходов);

  * безопасность (штраф за шашки, находящиеся под ударом).

  * обязательная поддержка серийных взятий: алгоритм должен рассматривать все возможные продолжения взятия как один ход.

**Производительность:**

* кэширование оценок позиций (Transposition Table);

* ограничение по времени на ход (например, не более 3–5 секунд).

### 5. LLM‑сервис (комментатор)

**Входные данные (JSON):**

```json

{

    "gameId": "uuid",
    "currentPlayer": "BLACK",
    "aiPlayer": "WHITE",
    "move": {
        "from": {"row": 3, "col": 2},
        "to": {"row": 5, "col": 4},
        "isCapture": true,
        "becomesKing": false
        },
    "boardState": "FEN-like string or compact JSON",
    "commentaryStyle": "friendly\_master"
}

```

**Стили комментариев (на выбор):**

* friendly\_master — опытный, доброжелательный, даёт короткие советы;
* competitive — азартный соперник, подбадривает и слегка «поддевает»;
* neutral — сухие факты и описание ситуации.


**Формат ответа:**

```json

{

    "comment": "О, ты меня подловил! Теперь я вынужден отступить, но не теряю надежды.",
    "style": "friendly\_master",
    "emotion": "concerned"

}

```

**Ограничения:**

* не предлагать свои ходы и не менять правила;
* длина комментария: 1–2 предложения (до 120 символов);
* использовать только допустимые ходы, которые уже выбраны алгоритмом;
* избегать токсичности и любых советов, нарушающих правила игры.


**Промпт‑шаблон (для LLM):**

> Ты — комментатор в игре «Шашки». Твоя задача — описать ход ИИ‑игрока, передать его эмоции и кратко пояснить мотивы. Не предлагай других ходов и не меняй правила. Стиль: {style}. Длина: 1–2 предложения.

### 6. Frontend (React + TypeScript + Vite)


#### 6.1. Компоненты

* **Board** — отрисовка доски 8×8 и шашек.
* **Piece** — шашка с индикацией цвета и статуса «дамка».
* **Highlight** — подсветка возможных ходов и взятий.
* **GameControls** — кнопки «Начать заново», «Сдаться», «Ничья».
* **CommentaryBox** — блок с комментарием ИИ после его хода.
* **StatusBar** — чей ход, счёт, статус игры.


#### 6.2. Интерактивность

* клик по шашке — подсветка возможных ходов;
* клик по целевой клетке — отправка хода на бэкенд;
* визуализация серийных взятий (анимация прыжков);
* анимация превращения в дамку (всплытие короны).


#### 6.3. Графика и стиль

* 2D‑стиль: плоские, но стильные элементы;
* цветовая палитра: тёплые тона дерева, контрастные шашки;
* тени и лёгкое 3D‑ощущение за счёт теней и бликов;
* опционально: SVG‑шашки или спрайты; для более красивой подачи — можно использовать Canvas или WebGL (если требуется высокая детализация).


#### 6.4. Анимации

* плавное перемещение шашки по диагонали;
* эффект «прыжка» при взятии;
* появление короны при превращении;
* пульсация клетки при выборе шашки.


#### 6.5. API‑интеграция

* использовать `axios` или `fetch` для запросов к бэкенду;
* обработка ошибок (невалидный ход, тайм‑аут, серверные ошибки);
* отображение состояний загрузки при ходе ИИ.

### 8. Тестирование


**Unit‑тесты (Java):**

* валидация ходов (все случаи: обычный ход, взятие, серия взятий, превращение);
* минимакс (проверка выбора лучшего хода на простых позициях).


**Интеграционные тесты:**

* полный цикл игры: старт → ход игрока → ход ИИ → комментарий → конец игры.


**UI‑тесты:**

* отрисовка доски и шашек;
* подсветка возможных ходов;
* отображение комментариев.

---

### 9. Критерии приёмки

* Игра корректно применяет правила шашек, включая обязательные взятия и серийные взятия.
* Ход ИИ всегда валиден и выбирается алгоритмом.
* Комментарий LLM соответствует стилю, не нарушает правила и не предлагает свои ходы.
* Интерфейс отзывчивый, анимации плавные, нет визуальных ошибок.
* Приложение запускается в Docker и работает в браузере.
