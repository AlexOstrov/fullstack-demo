## 4. Найденные замечания

Обозначения важности: 🟠 средняя · 🔵 низкая. Статус: `исправлено` / `открыто`.

### R-1. 🟠 Двойной учёт корневой позиции при обрезке ничьей в поиске — `исправлено`

**Файл:** `backend/src/main/java/com/example/backend/game/ai/AlphaBetaSearch.java`

`findBestMove` добавлял корневую позицию в `context.pathPositions`, тогда как `negamax` считает
вхождения как `gameRepetitions[key] + pathPositions[key]`, а `gameRepetitions`
(`GameState.positionRepetitions()`) **уже содержит текущую позицию** (конструктор `GameState`).
Итог — корень считался дважды: если позиция встретилась в партии 1 раз, а линия поиска возвращала
в неё ещё раз (реально 2 вхождения, ничьей нет), счёт давал `1 + 2 = 3` и узел оценивался как
ничья (0). ИИ «видел» ничью на повтор раньше реального (ТЗ 3.6).

**Эффект:** проявляется в эндшпилях при подключении API в Sprint 3 (в текущих тестах история
передаётся для позиции *после* хода, а не для корня, поэтому дефект не «выстреливал»).

**Исправление:** убрано добавление корня в `pathPositions` (кратность корня учитывает
`gameRepetitions`); обновлены Javadoc и комментарии контракта
(`positionRepetitions` включает текущую позицию, `pathPositions` — только ниже корня).

**Регрессия:** `AlphaBetaSearchTest#rootPositionIsNotCountedTwiceForRepetitionPruning`.
Проверено: до фикса тест падает (`−149` vs `−141`), после — зелёный. Кейс найден перебором:
228 из 20 097 позиций меняют оценку; для регрессии выбран детерминированный представитель
(белый K (0,1), чёрные K (4,3) + шашка (5,0), глубина 4).

### R-2. 🔵 Недостоверный `score`/`depth` при обрыве первой итерации — `открыто`

**Файл:** `AlphaBetaSearch.java:109–124`. Если таймаут наступает в первой итерации, ход
возвращается валидный (`rootMoves.get(0)`), но `score = 0`, `depth = 0`, что вводит в
заблуждение логи/анализ. Косметика; на корректность хода не влияет.

**Рекомендация:** при `completedDepth == 0` возвращать `depth = 0` явно как «не оценено» и/или
логировать; либо не рапортовать `score` для неоценённого ответа.

### R-3. 🔵 Пресеты ИИ не конфигурируемы через env — `открыто`

ТЗ 6.1 и §9 требуют `AI_PRESET_*` (и `GAME_TTL_MINUTES`). Значения захардкожены в `AiPreset`
(сами значения ТЗ соблюдены: 2/500, 4/1500, 6/3000; бюджет по умолчанию 1500, максимум 5000).
Ожидаемо для S3, но зафиксировать в плане.

**Рекомендация:** `@ConfigurationProperties` для пресетов/TTL в Sprint 3.

### R-4. 🔵 `AiPreset` не содержит `CUSTOM` — `открыто`

ТЗ 6.1 перечисляет `CUSTOM` среди пресетов. Реализация обходит enum и собирает `AiSettings`
напрямую (задокументировано в Javadoc). При Sprint 3 нужен явный маппинг
`Difficulty.CUSTOM → new AiSettings(aiDepth, aiTimeBudgetMs, tt)`.

### R-5. 🔵 `LlmComment` неполон для контракта LLM — `открыто`

`LlmComment(moveNumber, text, model, fallback)` не содержит `style`/`emotion`, тогда как ТЗ 7.5
и ответ API 5.2 требуют `emotion` и `commentSource`. Расширить в Sprint 4.

### R-6. 🔵 Мелкие замечания — `открыто`

- Дублирование копирования доски: `Board.copy()` и приватный `MoveGenerator.copy(Board)` —
  стоит свести к `Board.copy()`.
- `AlphaBetaSearch.java:91`: для сортировки корня передаётся `context.killer(depth - 1, …)` как
  номер плоскости (обычно `ply = 0`); семантически странно, безвредно.
- `application.yml` не содержит блоков `game`/`ai`/`llm` — появится в S3.
- Тестовые мелочи: имя `initialPositionHasFourWhiteForwardMoves` (по факту ходов **7**),
  сообщение «белых7» без пробела (`MoveGeneratorTest:21–22`).
- Остаточный демо-`items` (`ItemController`/`Item`/`ItemRepository`/`V1__create_items.sql`) —
  осознанное решение ADR-0009 (удаление в S3), не дефект.

### R-7. 🔵 Риск производительности (не дефект)

`PositionEvaluator.mobility` вызывает полную `generateMoves` для **обеих** сторон на каждом
листе; `MoveGenerator` копирует доску на каждом узле DFS взятий; TT на `1<<16` создаётся на каждый
ход. Бенчмарки S2.5 проходят (начальная позиция «тихая»), но в плотном миттельшпиле с серийными
боями запас бюджета сокращается. Отмечено в ADR-0013; проверить на Sprint 8 (профилирование).
